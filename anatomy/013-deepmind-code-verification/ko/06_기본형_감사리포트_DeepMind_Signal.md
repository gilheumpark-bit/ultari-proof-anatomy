## 2. 예상 반론 사전 사실 확인 (FAQ)

- Q1. "암호 프리미티브를 수학적 가정으로 치환하는 것은 표준이고 AArch64 바이너리도 검증한 것 아닌가?"
  - 사실 확인: 추적 64개 심볼 중 실제 AArch64 ELF 루틴을 직접 검증한 것은 9개(`14.06%`: `mallocng`, `memcpy`, `memset`, 파일 읽기; PR #2 이후 19개)이며, 55 / 64개(`85.94%`, PR #2 45 / 64 = `70.31%`)는 37개 Lean 명세 훅과 18개 패닉 스텁으로 대체되었습니다. 수학적 난제 가정을 공리화하는 것과 별개로, 컴파일된 AArch64 암호 구현 정당성(`HACL*`·`Fiat-Crypto`·`s2n-bignum`)과 `Drop::drop` 2개 dead-store 소거 여부는 검증 밖이며 `CliElfLib`(85,249줄)는 기본 `lake build`에서 제외됩니다.
- Q2. "`Arm64/Trusted` 공리적 TCB와 `ComparatorChallenge` 통과를 합치면 TCB가 충분히 좁고 검증된 것 아닌가?"
  - 사실 확인: ISA/시스콜 명세를 정리 0건 공리적 TCB(`16,767`줄)로 두는 설계 자체는 `seL4`·`CompCert`와 같으나 4대 자체 경계 미달분이 남습니다: (1) `arm64-semantics/ProofLib/TrustedClosure.lean:328-360`(커밋 `808b4b7ffef1`, `oai_ref` 미수록, 미수록 루트 `scripts/TrustedClosure.lean`과 별개)이 `VerifiedLibraries`·`CaseStudies`·`FormalRfcs`만 검사하면서 `"Arm64" :: _ => true`를 일괄 허용하고 시스콜 `31 / 301+`만 모델링, (2) `Hoare.lean`이 `.Exception` `177`개 분기를 fail-closed 배제하고 `mmap`이 `-ENOMEM` 대신 `.OutOfMemory`로 정지, (3) `AT_RANDOM` 0 초기화(`coins.rs` `.fill(0)`은 `Class A` 공시 경계이나 `HACL*`급 종단간 엔트로피 보장 밖) 및 `TESTING.md` `(1, 13)` 폴트 스킵, (4) [comparator/README.md](../proofs/oai_ref/comparator/README.md#L17-L18)에 **`Trusted.`** 심판기 기준선(`Symbolic/BugInjection/`과 별개)으로 명시된 `ComparatorChallenge`가 임포트 폐포 신뢰(`#L108-L116`) 아래 326개 파일(153,682줄)을 TCB 안으로 전이 임포트하고 `"enable_nanoda": false`와 PR #2의 67줄 주의사항 삭제를 동반해 TCB 격리 요건을 충족하지 못합니다.
- Q3. "PQXDH와 SPQR 증명이 양자내성 보안을 $2^{40}$ 규모에서 주장했는가?"
  - 사실 확인: `DEVIATIONS.md` (`DEV-PQ19`)가 밝히듯 계산 정리는 고전 보안만 형식화했으며, [PQXDH.md](../proofs/oai_ref/Computational/docs/PQXDH.md#L87-L115) `L115`는 점근 예산 $q_{\text{total}} = 2^{40}$에서 표준 모델 GapDH 제5항이 $17,441 / 16,384 \approx 1.0645 > 1$이 되는 점을 명시한 뒤 현실 예산 $q_{\text{total}} \le 2^{24}$에서의 구체적 보안 여유를 Class A 운용·보안 경계로 직접 산출해 공시합니다.
- Q4. "왜 `DEVIATIONS.md:2733`의 `DEV-C14` 임계치는 `38,967`인데 실제 상계는 `35,211`에서 1을 넘는가?"
  - 사실 확인: 코드의 수식이 변경된 뒤 [DEVIATIONS.md#L2733](../proofs/oai_ref/Computational/docs/DEVIATIONS.md#L2733)($q_{\text{ep}} = q$일 때 단일 세션 내 메시지/질의 수)의 본문 수치가 구수치(`38,967`) 그대로 방치되어 단일 세션 내 `3,756`개 메시지의 괴리가 발생했기 때문입니다([Comparator TCB & Crypto Bounds Module](../proofs/deepmind_comparator_laundering_and_crypto_bounds.lean#L1)).
- Q5. "그럼에도 추상 게임 귀착과 9개 직접 검증 심볼의 AArch64 정제는 공학적 가치가 있는가?"
  - 사실 확인: 매우 높습니다. `Computational/Proofs`의 다단계 암호 게임 귀착, `Symbolic/Proofs`의 Rust 기호 정제, 그리고 `mallocng`·`memcpy`·`memset` 기계어 증명은 AI 보조 형식 검증의 중요한 성취이므로 Gate 5: PASS로 분류했습니다.
- Q6. "TIER A로 승격되기 위한 수정 요건은 무엇인가?"
  - 사실 확인: (1) 기본 `lake build`에 `CliElfLib`를 포함하고 미도달 파일 1,450개(595,231줄)를 정리하며, (2) 153,682줄에 달하는 `ComparatorChallenge` TCB를 축소하고 `"enable_nanoda": true`·삭제된 67줄 주의사항 공시를 복구하며, (3) `DEVIATIONS.md:2733`의 `DEV-C14` 구수치를 `35,211`(`q = 7,327`)로 교정하고 누락된 감사 스크립트 5종·`TRUSTED_BASE.md`, 위생 자가시험, 미완성 `Synthetic/Disproofs` `sorry` 10건을 수리하며, (4) `55/64` 명세 훅·자체 `Arm64/Trusted` TCB 및 Class A 경계(`PQXDH.md` $q \le 2^{24}$, `DEV-CLI21` `.base-keys` `56,680`)를 표제에 명시하면 됩니다.
