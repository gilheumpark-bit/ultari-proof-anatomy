## 5대 핵심 인과 질문 (Q1~Q5)

### Q1. 기본 lake build와 위생 스크립트가 바이너리 증명을 상시 검증하는가?
- 대중적 인상: lake build와 자체 점검 스크립트가 전체 저장소를 상시 검증합니다.
- 커밋 808b4b7ffef1 실측 사실: 기본 lake build는 10,722개 모듈(7,258,642줄)만 빌드하며 [Computational/Theorems/Main.lean](../proofs/oai_ref/Computational/Theorems/Main.lean#L1-L103), [Symbolic/Theorems/Refinement.lean](../proofs/oai_ref/Symbolic/Theorems/Refinement.lean#L1-L59), [Symbolic/Theorems/Security.lean](../proofs/oai_ref/Symbolic/Theorems/Security.lean#L1-L90)이 속한 CliElfLib(120개 전용 모듈, 85,249줄) 등 592개 모듈(267,194줄)을 제외합니다. 또한 [정제 위생 스크립트](../proofs/oai_ref/Symbolic/scripts/check_refinement_hygiene.sh#L121-L136) 자가시험은 14개 보존 대상 정리(kept theorems) 중 7개가 사멸해 종료 코드 1로 즉시 실패하고, 617,448바이트 배치 ELF와 생성 Lean 코드는 AGPL-3.0-only 파생물이라 저장소에 커밋되지 않은 채 .gitignore로 빠져 있습니다([third_party/libsignal/README.md](../proofs/oai_ref/third_party/libsignal/README.md#L12-L59)).

### Q2. 컴파일된 AArch64 기계어와 메모리 소거·부채널을 끝까지 검증했는가?
- 대중적 인상: 암호 연산, 비밀키 영점화, 파일 I/O 기계어까지 모두 검증됩니다.
- 커밋 808b4b7ffef1 실측 사실: [CliBinaryPq.lean](../proofs/oai_ref/LibsignalBinary/Specifications/SignalSession/CliBinaryPq.lean#L137-L235)이 추적하는 64개 외부·런타임 심볼 중 9개 ELF 루틴(14.06%: 할당자·읽기·메모리 복사; PR #2 b0f729accbc2 이후 비암호 10개 추가로 19개 = 29.69%)을 직접 ELF 수준에서 검증했습니다. 반대로 55개(85.94%, PR #2 이후 45개 = 70.31%)는 명세 훅 및 패닉 스텁으로 치환되며(37개 cliHookTablePlaced 훅 + 18개 SIGABRT 패닉 스텁), 암호 26개 및 Drop::drop 영점화 2개 훅(black_box 1개 포함)은 수학적 난제 가정을 게임 인터페이스에 두는 것과 별개로 컴파일된 AArch64 암호 구현 정당성(HACL Star·Fiat-Crypto·s2n-bignum 대비), Drop::drop의 컴파일러 dead-store 소거 유지 여부, 타이밍·캐시 부채널은 ELF 기계어 검증 범위 밖이며 부팅 전 .data 5바이트를 0으로 덮어써 CPU 기능 탐지를 끕니다.

### Q3. Rust CLI 하네스, 공리적 Arm64/Trusted TCB 및 리눅스 시스콜 모델은 실제 환경과 일치하는가?
- 대중적 인상: 운영체제 난수·시계·비동기 DB와 표준 리눅스 커널을 그대로 따릅니다.
- 커밋 808b4b7ffef1 실측 사실: [coins.rs](../proofs/oai_ref/third_party/libsignal/libsignal-session/cli/src/coins.rs#L32-L46) 0 패딩 CryptoRng, 유닉스 기원 시각(UNIX_EPOCH = 0) 시계 고정 하네스 전제(DEV-PQ8·DEV-PQ9, [cli/src/lib.rs](../proofs/oai_ref/third_party/libsignal/libsignal-session/cli/src/lib.rs#L140-L250)), Waker::noop() 동기 폴링([handshake/src/lib.rs](../proofs/oai_ref/third_party/libsignal/libsignal-session/cli/handshake/src/lib.rs#L58-L65), [ratchet/src/lib.rs](../proofs/oai_ref/third_party/libsignal/libsignal-session/cli/ratchet/src/lib.rs#L61-L68))은 원고·DEVIATIONS.md가 Class A로 자진 공시한 하네스 경계입니다. 한편 최하위 Arm64/Trusted/(61개 파일, 16,767줄)는 seL4·CompCert처럼 설계상 정리 0건인 공리적 ISA/시스콜 TCB이나, 31 / 301+ 시스콜만 다루고 Sail/Unicorn 차등 시험([TESTING.md](../proofs/oai_ref/arm64-semantics/Arm64/TESTING.md#L124-L132))은 결함 상태 (1, 13)과 DC ZVA·ADDV를 건너뛰며 mmap 고갈 시 -ENOMEM 대신 .OutOfMemory(Spec.allowOom 면책)로 정지합니다. 저장소 전체 38건 sorry도 정상 ComparatorChallenge 표적 자리표시자 24건 및 부정 픽스처 4건과 구분되는 미완성 Synthetic/Disproofs 스텁 10건을 포함합니다.

### Q4. comparator 심판기와 인간 검토 TCB 경계는 얼마나 좁은가?

[computational.json](../proofs/oai_ref/comparator/computational.json#L19-L19)과 [symbolic.json](../proofs/oai_ref/comparator/symbolic.json#L23-L23)은 nanoda를 끄고 landrun 바깥에서 .olean을 선행 빌드하며, PR #2(b0f729accbc2)에서는 Linux 5.10 비샌드박스·챌린지 변경 가능성 고지 67줄(L65-L131)이 삭제(138 -> 101줄)되었습니다.

### Q5. Class A 자진 공시 운용·보안 경계와 Class B 미공시 문서 결함은 어떻게 구분되는가?
- 대중적 인상: 양자 컴퓨터 공격과 $2^{40}$ 배포 규모까지 무조건 성립하고 문서와 코드 수치도 완전히 일치합니다.
- 커밋 808b4b7ffef1 실측 사실: Class A 자진 공시 운용·보안 경계로서 계산적 정리(DEV-PQ19)는 고전 안전성만 증명하며(HNDL 미주장), [PQXDH.md](../proofs/oai_ref/Computational/docs/PQXDH.md#L87-L115)는 $q_{\mathrm{total}} = 2^{40}$(stepCostBudget 약 $2^{96.00}$)에서 표준 모델 GapDH 제5항이 $17,441 / 16,384 \approx 2^{+0.10} > 1$인 점근적/정성적 영역임을 밝히고 L115에서 구체적 비공허 보안 여유를 $q_{\mathrm{total}} \le 2^{24}$로 명시 산출합니다. 기호 래칫 정리 또한 공격자 선택 pqSalt로 고전 비퇴행만 보증하고 TRKeyKnown에서 macKey·iv를 제외하며, 이진 ValidCall은 고정 2자·사전 공유 공개키·1+1 및 선택적 일회용 프리키 등 5개 절로 트레이스를 제한합니다([PAPER_DIFFERENCES.md](../proofs/oai_ref/docs/Symbolic/PAPER_DIFFERENCES.md#L173-L324)). 또한 DEV-CLI21([DEVIATIONS.md](../proofs/oai_ref/Computational/docs/DEVIATIONS.md#L3474-L3528))에 따라 .base-keys(37바이트/키)는 56,680번째 핸드셰이크($2,097,160 > 2^{21}$ B) 이후 미회전 최후수단 Kyber 프리키 수락만 상한 거부(Outcome.exited 1 [])되며 기존 세션의 송수신과 일회용 프리키 처리는 L3522-L3524에서 명시한 대로 정상 지속됩니다. 반대로 Class B 미공시 결함으로서 DEVIATIONS.md:2733(DEV-C14)은 8바이트 MAC 상한이 실제로 $q = 35,211$개 메시지에서 1을 넘는데도 구수치 38,967을 그대로 적고 있으며, DEVIATIONS.md 상단 요약표(207 대 활성 206 + 인라인 4), check_refinement_hygiene.sh 자가시험 7/14 실패, 미수록 0/6 감사 파일, PR #2의 comparator/README.md 67줄 삭제가 존재합니다.

## 비전공자를 위한 6단계 직관적 해부

1. 기본 빌드 제외 지층과 미커밋 AGPL-3.0-only 바이너리: [lakefile.lean](../proofs/oai_ref/lakefile.lean#L1-L120) 기본 타깃에는 10,722개 모듈만 포함되고 CliElfLib 전용 120개 모듈(85,249줄)은 제외됩니다. 더 나아가 증명이 가리키는 617,448바이트 ELF(SHA-256: 2f20c836...)는 Signal의 AGPL-3.0-only 코드에서 파생되어 Apache-2.0 저장소에 커밋되지 않으며, 소스 헤더 줄 번호가 패닉 기계어에 박혀 있어 주석 한 줄도 바꿀 수 없습니다. 한편 LibsignalBinary/Heap/(22개 SYNC.txt 미러 파일 포함)은 어떤 헤드라인 정리도 임포트하지 않는 고립 지층으로 남아 있습니다.
2. 55/64 (85.94%) 명세 훅·패닉 스텁 치환과 암호 구현·영점화·부채널 경계: 64개 추적 심볼 중 직접 ELF 루틴 9개(PR #2 이후 19개)가 기계어 실행으로 검증된 반면, 55개(PR #2 이후 45개) 호출 지점은 37개 명세 훅과 18개 패닉 스텁으로 치환됩니다. 암호학적 난제 가정을 게임 인터페이스에 두는 것과 별개로, 26개 암호·배리어 및 2개 Drop::drop 영점화 훅과 컴파일된 AArch64 암호 구현(HACL Star·Fiat-Crypto·s2n-bignum 영역)·컴파일러 dead-store 소거 유지 여부·캐시 및 타이밍 부채널 누출은 검증 범위 밖입니다.
3. Class A 자진 공시 하네스 경계(시계 고정 전제·0 패딩 난수기·동기식 단일 파일): 실제 Signal 앱은 OS 난수기, 실시간 시계, 멀티스레드 비동기 SQLCipher DB, 네트워크 재전송 위에서 동작합니다. DeepMind가 원고·DEVIATIONS.md에 Class A로 자진 공시한 범위 위에서 검증 대상 CLI는 Coins 0 패딩 구조체, 1970년 1월 1일(UNIX_EPOCH = 0, DEV-PQ8) 시계 고정 하네스 전제(30일 만료 로직 DEV-PQ9 비활성화), 닫힌 표준입출력(EBADF = 9) EOF 처리를 씁니다.
4. 부팅 전 5바이트 .data 초기화 패치, udf #0 스텁, OutOfMemory 면책: Eval.lean이 MRS 명령에서 정지하므로 부팅 전 .data 5바이트를 0으로 초기화하고, 링커 검증기([alink_check.py](../proofs/oai_ref/scripts/stock-pin/alink_check.py#L21-L31))는 미정의 외부 심볼과 약한 원자 연산 3종을 4바이트 udf #0(0x00000000) 트랩 스텁으로 채웁니다. 또한 Mmap.lean은 1 GiB 초과 시 -ENOMEM 반환 대신 .OutOfMemory로 정지해 널 포인터 역참조 경로를 면책합니다.
5. Class A 고전 전용·$q_{\mathrm{total}} \le 2^{24}$ PQXDH 구간(DEV-PQ19, PQXDH.md:87-115): PQXDH + SPQR이라는 프로토콜 이름과 달리 계산적 정리는 고전 안전성만 다루며, 배포 규모 $q_{\mathrm{total}} = 2^{40}$에서는 리덕션 스텝 예산이 $2^{96.00}$에 달해 표준 모델 Curve25519 4-leg GapDH 항이 $17,441 / 16,384 > 1$이 되므로 저자들은 PQXDH.md:87-115에서 구체적 비공허 보안 구간을 $q_{\mathrm{total}} \le 2^{24}$로 명시 제한합니다. 또한 단일 키 X25519+XEdDSA 공유(DEV-PQ13)의 GapSigEufCma와 GapDhWithSign Forking-Lemma 제곱근 손실은 독립 모듈 XeddsaRom/과 함께 Lean TCB 밖에 남아 있고, DEV-PQ16은 소수 위수 부분군 검사(P.isCanonical)를 강제(바이너리에서는 비틀림 검사를 훅으로 대체)하는 반면 DEV-PQ17은 코팩터-8 비틀림 동치류(pow8)로 감축하여([DEVIATIONS.md](../proofs/oai_ref/Computational/docs/DEVIATIONS.md#L1894-L1922)) $O(q_{\text{total}}^2)$ DDH 오라클 예산을 요구합니다.
6. Class B DEV-C14 구수치 불일치(35,211 대 38,967) 대 Class A .base-keys 56,680 상한(기존 세션 유지): 8바이트 절단 와이어 MAC 때문에 SPQR V1 합성 상한(DEV-C14)은 $q_{\mathrm{ep}} = q$에서 $q = 35,211$개 메시지부터 1을 넘으며(DEVIATIONS.md:2733은 구수치 38,967 오기재; 16바이트 MAC 확장 시 $q = 2,307,621,357 > q_{\mathrm{u32,\max}}$로 단일 세션 공허화 완전 제거), .base-keys 파일은 DEV-CLI21에 공시된 대로 56,680번째 핸드셰이크($2,097,160 > 2$ MiB) 이후 미회전 최후수단 Kyber 프리키 신규 수락만 상한 거부하며 기존 세션의 송수신·whisper 수신·일회용 프리키 수신은 정상 작동합니다.
