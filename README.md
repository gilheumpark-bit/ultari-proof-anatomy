> **Two-Track Verification Method**: **(1) Full-Corpus Static, Call-Graph & TCB Parsing** across all 44,833 distinct upstream `.lean` files (`oai_ref/` line-anchored) + **(2) Standalone Zero-`sorry` Lean 4 Re-Proofs** of exact algebraic/analytic invariants, constants, and barriers (`Init`/`Std` in 13 cases for sub-minute mutation testing; `Mathlib 4` over $\mathbb{R}$ in Cases 010 & 015).

## Core Mission: What This Repository Does

1. **Reverse-Engineering Hardcoded Constants & Proof Margins**:
   - Large formal proofs often replace exact roots with rational proxies or loose upper bounds (`gcongr`, `linarith`) to close goals quickly.
   - We trace these proofs line by line to recover the exact equations and measure the unused slack inside the bounds.
2. **Drawing a Strict Boundary (`Ultari`) Between Proved & Open**:
   - Every claim in this archive is backed by standalone, zero-`sorry` **Lean 4** theorems and **SymPy** scripts.
   - Each case separates what the code actually proves from what remains open or relies on simplified model assumptions.
3. **4-Tier Guides (+ Referee Audit Reports) for Every Reader**:
   - Every case folder provides four core guides in both English (`en/`) and Korean (`ko/`), and audited cases add Tiers 5–6 (`05_*` Detailed Referee Reports & `06_*` Summary Scorecards):
   - **Tier 1 (`01_Beginner`)**: Plain-language overview of the problem and findings without heavy formulas.
   - **Tier 2 (`02_Intermediate`)**: Core equations and a 1-to-1 Lean theorem & line-number index.
   - **Tier 3 (`03_Expert`)**: Full referee report, cross-check tables, and scope boundaries.
   - **Tier 4 (`04_Automated` & `manifest.json`)**: 1-line check commands and SHA-256 checksums.
   - **Tiers 5–6 (`05_*` & `06_*`)**: Full 5-gate forensic referee reports and executive audit scorecards (per [`AUDIT_CHARTER.md`](./AUDIT_CHARTER.md)).

## One-Command Repository Verification

> **Toolchain & Scope Note**: Cases 001–009 and 011–014 intentionally isolate exact rational, polynomial, and integer invariants in standalone `Lean 4` (`Init`/`Std` + `Python 3` `sympy`, zero external library TCB, sub-minute mutation testing, with continuous analytic hypotheses explicitly bounded in each Tier 3 report), while Cases 010 and 015 formalize real-analysis and calculus barriers directly over `Mathlib 4` ($\mathbb{R}$, `HasDerivAt`). The 13 standalone `Init`/`Std` suites were authored against baseline `Lean v4.29.0-rc8` and compile identically under root-pinned `Lean v4.35.0`, while Cases 010 and 015 target `Lean v4.35.0` + `Mathlib v4.35.0` (pinned via root `lean-toolchain`, `lakefile.toml`, and `lake-manifest.json`). Run `lake exe cache get` once at the repo root to fetch precompiled `Mathlib 4` binaries (auto-resolved via `.lake/` or `LEAN_PATH`), or pass `--standalone-only` to verify the 13 `Init`/`Std` cases immediately without `Mathlib`.

Run [`tools/verify_all.py`](./tools/verify_all.py) from the repo root to run all five checks:
1. **Lean 4 Kernel Check**: Compiles every `.lean` file with zero `sorry` and zero custom `axiom` (`exit 0`).
2. **Symbolic Solver Check**: Runs every `SymPy` script and checks for an exact match with the locked JSON output.
3. **SHA-256 Checksum Check**: Verifies all artifact hashes against each `manifest.json` and `04_*.md` table.
4. **1-to-1 Theorem Link Check**: Verifies every theorem name and `#L` line link across all English and Korean guides.
5. **Hypothesis Mutation Check**: Replaces each theorem premise with `True` one by one and confirms the Lean compiler rejects every mutant.

```bash
sha256sum -c MANIFEST.sha256
lake exe cache get          # one-time Mathlib 4 binary fetch for Cases 010 & 015
python3 tools/verify_all.py # or: python3 tools/verify_all.py --standalone-only
```
